## Planning and review

Budgets use integer satang for allocation and daily schedules; rounding remainder is assigned to the first days so totals match exactly. Mode changes the testing approach, not the chosen goal or promised performance. The 80/20 allocation is an explicitly explained starting heuristic only when the owner reports an existing usable audience; otherwise all spend stays in one prospecting group. No minimum Meta budget or audience eligibility is asserted.

Result ranges require user-supplied low/high costs. Messages, clicks and purchases divide total spend by cost; awareness uses CPM and reports impressions, never unique reach. No benchmark CPM/CPC/CTR, forecast conversion rate or invented ROAS is inserted. Profit enables an arithmetic break-even order count, clearly distinguished from forecast sales. Original caption/prices are preserved. CTA comes from the pinned Brand Kit. The owner can review/acknowledge, download a text plan, and reuse inputs to create a separate immutable plan. Unsaved form edits are not persisted.

## Optional AI

`ADS_ANALYSIS_MODEL` plus `GEMINI_API_KEY` enables an explicit consent checkbox. The provider receives the caption, supplied game and optionally a resized owned image. It does not receive cookies/tokens, the Facebook URL, shop contacts, budget or profit. Video content is not analyzed. Output is constrained to yes/no/unclear checks for offer, CTA, game match and image legibility. Server validation discards additional fields; model output cannot change prices, budgets, estimates, claims or campaign settings. This is a bounded content review, not unrestricted copy generation or a truth/policy checker.

With AI disabled, the page explicitly presents deterministic planning and a self-review checklist. Provider failure preserves the saved arithmetic plan and marks analysis as fallback; it consumes one saved-plan allowance, since the plan remains usable. Running analyses abandoned for over two minutes are marked fallback when the owner next reads or accepts a plan. Late responses cannot overwrite recovered rows. There is no automatic paid retry. Live provider quality, billing, private Blob reads and hosted timeout behavior need staging verification; local tests replace the provider boundary and make no paid calls.

## Data and rollout

Apply `db/migrations/20260920_ads_planner.sql` after M1–M4. Tables: `ads_entitlements` and `ads_plans`. No existing plan receives access automatically. Explicit shop grants determine monthly saved-plan limits (UTC); the shop row lock serializes quota checks and duplicate submissions. There is also a 10-plan/hour cap. Request UUID plus normalized input hash ensures retry idempotency. Plans pin the immutable Brand Kit version and snapshot the source asset name. Assets remain governed by M2 retention; deleting one does not remove the plan and the UI shows that it is unavailable. Plans are listed newest first, up to 100; no automatic plan deletion is implemented.

Routes: authenticated `GET/POST /api/ads-plans`, and same-origin confirmed `POST /api/ads-plans/[id]`. Ownership is checked in SQL, asset readiness is checked on creation, mutations enforce origin, body size is bounded, and text is rendered as escaped React content. Acceptance is a local review marker, never authorization to spend.

Local demonstration uses `scripts/media-test-server.mjs`, which applies migrations to a fresh disposable PostgreSQL cluster and disables AI credentials. `scripts/ads-demo-access.mjs` grants only the fixed `ads-ui@example.test` review account on that verified loopback fixture. No live migration or production deployment has been performed.

## Meta source boundary
